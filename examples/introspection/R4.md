# R4 — Dynamic Topic Read / Dynamic Parameter Get-Set

```text
Discovery:    Supervisor → Runtime → Endpoint
Description:  Endpoint.type_id → TypeDescriptor
Actual access:
  Topic       → DynamicTopicReader     → latest SHM bytes
  Parameter   → DynamicParameterClient → current SHM bytes / Set
Service: NOT IMPLEMENTED
Dynamic callback / StartMonitor / streaming: NOT IMPLEMENTED
```

## Public API

Include `kcf/dynamic/dynamic_topic_reader.hpp` or
`kcf/dynamic/dynamic_parameter_client.hpp` and link `kcf_core`. Application payload
headers, physical SHM names, mappings, storage layout and synchronization details
are not part of this API. No application `T` is instantiated by either client.

```cpp
kcf::TypeDescriptor descriptor;
int result = introspection.GetType(runtime, endpoint.type_id, descriptor);
if (result != 0) return result;

kcf::DynamicTopicReader reader;
result = reader.Open(endpoint.name, endpoint.type_id, descriptor);
if (result != 0) return result;
kcf::DynamicPayload sample;
result = reader.ReadLatest(sample); // -EAGAIN: retry at a later polling interval
reader.Close();
```

For a PARAMETER endpoint:

```cpp
kcf::DynamicParameterClient parameter;
int result = parameter.Open(endpoint.name, endpoint.type_id, descriptor);
if (result != 0) return result;
kcf::DynamicPayload value;
result = parameter.Get(value);
if (result != 0) return result;
// The caller edits bytes using the validated descriptor, preserving valid native
// representations and any application-specific constraints.
result = parameter.Set(value);
parameter.Close();
```

`Open(name, descriptor)` is shorthand for
`Open(name, descriptor.type_id, descriptor)`. A descriptor is deliberately required;
`name + ID` alone cannot verify the expected payload size, alignment or field layout.
Caller-supplied ID must be nonzero and equal the descriptor ID. This is the R4 API
refinement over the conceptual two-argument name/ID example.

`DynamicPayload` contains a uint64_t `type_id`, uint64_t `sequence`, and a local
`std::vector<std::byte> bytes`. It owns a copy, never a pointer into shared storage.
The vector is never stored in SHM. Successful reads replace the caller's result;
failed Open/ReadLatest/Get leave existing output unchanged. Close is idempotent;
operations on a closed client return -EBADF, opening an open client returns -EBUSY.
A failed Open releases the temporary fd/mapping and may be retried on that object.

## Actual storage identity and validation

SharedChannel and SharedParameter store a validated declaration's stable `type_id`
and a layout fingerprint in their immutable initialization header. Identity is
computed only at Create, directly from `TypeDescriptorTraits<T>` without registry
access. Missing, throwing, invalid or size/alignment-inconsistent traits produce
zero identity and do not fail typed Create. Storage identity does not depend on a
running ProcessRuntime, registration capacity or discovery availability. A failed
metadata registration can still leave EndpointInfo.type_id=0 as in R3.

Dynamic Open validates the R3 descriptor (including field names, primitive widths,
bounds and overlap), actual magic/format/initialization/owner, nonzero matching type
ID, matching layout fingerprint, exact payload size/alignment and exact total file
size before touching shared synchronization. Alignment must fit the local mmap page
alignment. Initialization locking is nonblocking; a busy initializer is retryable.
The layout is computed inside KCF using the same internal storage declarations as
typed IPC, including slot stride and padding for over-aligned payloads.

The internal format-3 fingerprint uses FNV-1a over type ID, NUL-terminated canonical
name, payload size/alignment, field count, then each ordered field's NUL-terminated
name, kind, offset, element size and array count. Integers are encoded as eight
least-significant-byte-first bytes. Padding, reserved bytes and unused fields are
excluded. It catches same-ID/different-layout declarations, and is not a
cryptographic identity or collision-free guarantee. R3's public stable type ID
algorithm is unchanged. Explicit declarations remain the application's responsibility.

Read/Get/Set recheck actual mapped header identity/size/alignment/format. Set also
requires value.type_id equal to the opened identity and exact byte count. Failed
validation does not acquire the parameter transaction lock or write payload bytes.
Get/ReadLatest revalidate after copying before returning a result. These are
cooperating local IPC contracts; external concurrent header mutation or truncation
of an open mapping is not a supported access mode or security boundary.

Errors include -EINVAL (invalid descriptor/zero ID/caller ID disagreement),
-EPROTOTYPE (actual type or layout mismatch), -EMSGSIZE (actual payload size/alignment
or Set byte count), -EPROTO (incompatible/malformed storage), -EAGAIN (uninitialized,
dead owner, initialization lock busy or no stable Topic snapshot), and -ENOMEM.
Other existing negative errno results propagate. No registry polling occurs in
Open/ReadLatest/Get/Set; the caller obtains a descriptor before Open.

## Source compatibility and storage format

The internal SHM format changes from **2 to 3**; type/layout identity extends the
owner header from 40 to 56 bytes. All peers sharing a storage object must be rebuilt
against R4 and restarted together. Old complete objects are rejected, not silently
reinterpreted or migrated/reclaimed as format 3. Stop old peers and perform explicit
owner cleanup of old objects before using the same names. The existing recovery
rules for known dead format-3 owners and incomplete initialization remain in force.

Publisher<T>, Subscriber<T>, Parameter<T> and underlying typed API signatures are
unchanged. Undefined types still operate with type_id=0; dynamic access rejects
them. Typed Open retains its existing size/alignment contract; only the dynamic
client requires semantic identity. A stale descriptor for a reused name with a
new type or layout fails Dynamic Open even if payload sizes are equal.
Already-open clients retain their original mapping after unlink/replacement, like
typed peers: no hot reconnect, name re-resolution or liveness guarantee is added.

SystemStatus's public model/protocol and Bringup control behavior are unchanged;
its underlying SharedParameter transport also uses format 3. Existing white-box
crash/recovery test fixtures were updated for the new header, without changing
their assertions or adding production injection APIs.

## Topic snapshots and isolation

ReadLatest makes at most 32 snapshot attempts and returns -EAGAIN on contention or
before first publication. It uses the same reader pin/version/sequence copy helper
as typed SharedChannel reads, and never takes the notification mutex or starts a
worker. A successful sample's sequence belongs to its copied bytes. The underlying
32-bit Topic sequence is widened into the result and wraps modulo 2^32; it is not
a monotonic lifetime counter across wrap or publisher restart.

No type declaration/registry lookup was added to Publish. A reader paused/killed
inside memcpy leaves at most its acquired pin. A single such pin leaves two slots
available, and the test continues publishing successfully while it is stopped and
after SIGKILL. Multiple abandoned pins can exhaust non-published slots and make
Publish return -EAGAIN; it never waits for those readers. This pre-existing limitation
is preserved, not solved by R4. Polling readers must handle -EAGAIN. ReadLatest copies
bytes and allocates a caller-local result; it is a Tool observer path, not a real-time
control primitive. Serialize reads for the usual one-reader-per-local-object model.

## Parameter transaction and notification

Typed and dynamic Get/Set share the same internal byte access helpers, actual
robust process-shared mutex, two payload slots, version transaction and condition
broadcast. Get returns the value and version under one lock. Set updates the
inactive slot, commits, increments uint64_t version, unlocks and broadcasts. Existing
typed watcher callbacks observe dynamic changes as ordinary Parameter changes;
callbacks may coalesce multiple updates, as before. Version exhaustion returns
-EOVERFLOW. Set ignores DynamicPayload.sequence: it is not compare-and-swap and
concurrent writers use last successful transaction wins.

Get/Set may overlap across typed/dynamic clients and on one dynamic parameter
client. Stop/join all local calls before Close, destruction or Open. No new mutex
hierarchy or private Tool parameter storage is used. A killed Get reader releases
the robust lock through the next locker’s recovery; a killed writer before commit
rolls back to the previous active slot/version. A live paused parameter lock holder
can still delay other parameter operations under the existing blocking contract;
robust recovery handles death, not a permanently paused live owner. -ENOTRECOVERABLE
and other existing synchronization failures remain possible. A notification error
after a committed Set can be reported after the new value is already visible,
matching typed Set semantics.

This layer transports bytes; it does not format field values, validate application
ranges, convert endianness, or implement field-wise updates. Tool Interface will
combine these bytes with R3 metadata. Native payload layout and representation are
local producer ABI facts, not portable serialization.

## Validation

Build and run from the worktree (actual POSIX SHM and local process IPC required):

```sh
cmake -S . -B build-r4-clean
cmake --build build-r4-clean -j 4
./build-r4-clean/examples/introspection/kcf_dynamic_access_test
```

R4 tests cover Topic known A/B values and sequence, all 10,000 concurrent publishes
succeeding with consistent dynamic snapshots, same-size semantic mismatch, same-ID
layout mismatch, stale same-name replacement, undefined Topic/Parameter typed IPC,
Parameter Get/Set and typed watcher notification, failed writes preserving value
and version, 6,000 concurrent typed/dynamic transactions, byte-aligned and 64-byte
aligned payloads, escaped logical names, current storage identity corruption,
old-format rejection, and Supervisor → Runtime → Endpoint → Type → actual data.

The crash executable compiles the real dynamic source with test-only link wrapping
of memcpy (and -fno-builtin-memcpy). It stops a child inside the actual copy after
the Topic pin or Parameter lock, then SIGKILLs it. It checks continued publishing,
Get recovery and interrupted Set rollback. Production has no crash/sleep hooks.

R1–R3 and existing lifecycle/supervision, Supervisor loss, Reset/recovery, Topic,
Parameter, SystemStatus and Integration regression results are recorded after the
final clean build. No kcf_tool/mecanum changes, dev reset, commit or push.
