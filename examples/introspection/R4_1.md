# R4.1 Dynamic SHM Recreate Detection Result

Worktree: `/tmp/kcf-r1-introspection`, branch `feature/introspection`.
R1–R5의 기존 변경을 보존했습니다. commit/push/reset은 하지 않았습니다.

## 계약과 구현

DynamicTopicReader / DynamicParameterClient는 성공한 Open 당시의 POSIX SHM object에
묶입니다. 이후 동일 이름이 unlink되거나 다른 object로 재생성되면 접근 시 `-ESTALE`을 반환합니다.
PID, process_start_ticks, type_id, payload size/layout이 같아도 object가 다르면 stale입니다.
자동 reopen은 없습니다. caller가 기존 instance를 유지하고 오류 후 Close → metadata refresh → Open을
명시적으로 결정해야 합니다. 매번 새 instance로 Open하면 그때의 새 object에 새로 묶입니다.

`kcf/src/dynamic_access.cpp` 내부 SharedObjectIdentity가 Topic/Parameter의 공통 검증을 제공합니다.
Open에서 기존 fd의 fstat 결과 중 st_dev/st_ino와 내부 인코딩된 이름을 process-local하게 저장합니다.
기존 fd는 instance가 닫힐 때까지 유지되므로 해당 inode가 그 사이 재사용되지 않습니다.

검증은 `shm_open(O_RDONLY | O_CLOEXEC)` → fstat → 임시 fd close 순서입니다.
이름이 없거나 device/inode가 다르면 `-ESTALE`, 다른 OS 오류는 해당 negative errno입니다.
임시 fd는 fstat 실패 시에도 닫습니다. 원본 fd에도 O_CLOEXEC을 사용합니다.
fd/inode/physical name은 public API나 Tool에 노출하지 않습니다.

Open 마지막 검증과 ReadLatest/Get의 copy 전후, Set의 쓰기 전 검증에 같은 identity check를 적용합니다.
이미 stale인 Get/ReadLatest는 output을 보존하고 copy 전에 실패합니다.
이미 stale인 Set은 기존 Parameter synchronization/write에 들어가기 전에 실패합니다.
새 owner뿐 아니라 기존 old mapping의 값도 변경하지 않는지 테스트했습니다.

SHM layout/format은 **3 그대로**이며 generation field를 추가하지 않았습니다.
Service protocol은 **2 그대로**, Service 구현은 수정하지 않았습니다.
Publisher/Subscriber/typed Parameter hot path에는 syscall/registry lookup/lock을 추가하지 않았습니다.
Introspection polling, timer, monitor, cache thread를 추가하지 않았습니다.

### 동시성 범위

이름 검증은 시점 검사이며 POSIX namespace의 unlink와 payload access를 하나의 원자적 transaction으로
묶지는 않습니다. 검증 직후 다른 프로세스가 unlink하는 경합까지 막는 namespace lock은 없습니다.
Read/Get은 copy 후에도 검증하여 관측한 교체를 caller에게 성공으로 전달하지 않습니다.
Set 검증 이후 실행 중인 write와 동시에 unlink가 발생하는 경우의 원자적 취소는 보장하지 않습니다.
재생성이 완료된 뒤 호출한 old client의 Get/Set은 반드시 stale로 거부합니다.
기존 Parameter robust synchronization과 Topic pin/crash limitation은 그대로입니다.

## KT-4 Requirement: FAIL — Tool의 reader 수명 연결이 별도로 필요

현재 KcfBackend는 모든 polling tick에서 새로운 DynamicTopicReader를 Open/Read/Close합니다.
따라서 매번 새로운 object identity를 캡처하고 이전 tick의 object와 비교할 수 없습니다.
이는 이번 public instance 계약을 사용할 때 필요한 reader 유지가 아직 연결되지 않은 상태입니다.

Tool source를 변경하지 않은 임시 Qt probe에서 같은 process/name/type/layout으로 SHM을 재생성했습니다.
결과: `KT4 recreate detection: FAIL (timer still running); displayed x=9.5`.
즉 새 object 값을 계속 표시하며 기존 Echo가 자동 중지되지 않는 것을 실제로 확인했습니다.

현재 GUI는 backend의 negative errno를 이미 Echo Stop/status 표시로 전달합니다.
GUI workaround나 physical SHM 접근을 추가할 필요는 없습니다.
완전한 KT-4 연결에는 Prepare 시 연 DynamicTopicReader를 해당 Echo 동안 유지하고
Stop/Refresh 시 Close하도록 **KcfBackend reader 수명 관리**를 변경해야 합니다.
이번 요청의 Tool 수정 금지를 지켜 해당 변경은 수행하지 않았습니다.

기존 Tool 테스트를 새 core에 링크하여 확인했습니다. 최초 실행은 3/5 PASS였고,
backend discovery/첫 publish 준비와 관련된 것으로 보이는 assertion 두 곳이 실패했습니다.
빌드 종료 후 실패한 두 테스트를 소스 변경 없이 재실행하자 2/2 PASS했습니다.
기존 테스트의 startup timing 의존성이 남아 있으므로 이 이력을 숨기지 않습니다.
이 재실행 통과가 위 same-type recreate Echo 조건의 통과를 의미하지는 않습니다.
