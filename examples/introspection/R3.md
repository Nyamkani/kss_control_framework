# R3 — Stable Flat Type Descriptor

Continues R1–R2B on `feature/introspection` in `/tmp/kcf-r1-introspection`.

```text
Discovery: Supervisor → Runtime → Endpoint
Type:      Endpoint.type_id → TypeDescriptor
Actual Data: NOT IMPLEMENTED
```

Supervisor stores no descriptors. The selected Runtime owns its descriptor registry;
type resolution must use the same PID/start-ticks generation as endpoint discovery.

## Public contract

Include `kcf/introspection/type_descriptor.hpp` for FieldValueKind, TypeFieldInfo,
TypeDescriptor, StableTypeId, TypeDescriptorTraits and declaration helpers.
All metadata structures are fixed POD/trivially copyable. TypeDescriptor supports
at most 128 named flat fields; each has a primitive kind, offset, element_size and
array_count. Fixed primitive arrays have one field with count > 1.

Supported kinds are BOOL (1 byte), INT8/UINT8, INT16/UINT16, INT32/UINT32,
INT64/UINT64, FLOAT32/FLOAT64 (IEEE-754). No dynamic strings/containers, pointers,
unions, variants, recursive structures or enum semantic mappings are supported.
The helper accepts one-dimensional fixed C arrays of these primitives. Nested POD
members are declared as flat paths and summed offsetof expressions, not a tree.

### Stable identity

`StableTypeId(canonical)` is FNV-1a 64-bit over exact canonical name bytes, excluding
the terminating NUL: initial hash 14695981039346656037, XOR each unsigned byte,
multiply by 1099511628211 modulo 2^64. There is no locale, encoding normalization,
RTTI, compiler name or layout hash. For example, `StableTypeId("hello")` is
`0xa430d84680aabd0b`. The same bytes produce the same ID in any process/build.

Registered canonical names must be nonempty, NUL-terminated and fit in 159 bytes;
embedded NUL is rejected by the declaration helper. No silent name truncation is
used for stable names or field names. Applications should use versioned canonical
names such as `kcf.test.TestData.v1`, changing the version on incompatible semantic
or layout contract changes. ID 0 is invalid. FNV is not cryptographic and does not
guarantee collision freedom. Never use the ID as a security credential.

### Explicit declaration

```cpp
struct TestData {
    std::uint64_t sequence;
    float x;
    std::int32_t count;
    float values[4];
};

namespace kcf {
template<> struct TypeDescriptorTraits<TestData> {
    static constexpr bool defined = true;
    static TypeDescriptor Get() noexcept {
        auto d = MakeTypeDescriptor<TestData>("kcf.test.TestData.v1");
        d.field_count = 4;
        d.fields[0] = MakeField<TestData, std::uint64_t>("sequence", offsetof(TestData, sequence));
        d.fields[1] = MakeField<TestData, float>("x", offsetof(TestData, x));
        d.fields[2] = MakeField<TestData, std::int32_t>("count", offsetof(TestData, count));
        d.fields[3] = MakeField<TestData, float[4]>("values", offsetof(TestData, values));
        return d;
    }
};
}
```

The specialization must be visible before wrapper instantiation and consistent
across translation units. Default traits have `defined=false`; no source changes
are required for existing types. Helpers require standard-layout, trivially
copyable non-union owners and known primitive members. Explicit declarations are
application responsibility: standard-layout/trivially-copyable alone cannot
prove that an aggregate contains no pointer or that a hand-written field kind
matches the actual member. R3 does not attempt arbitrary reflection or member
inspection. Do not declare unsupported members as a supported primitive kind.

For nested POD, use e.g. name `header.timestamp_us` and
`offsetof(Outer, header) + offsetof(Header, timestamp_us)`. See
[the test declarations](include/r3_test_types.hpp) for a complete flat example.

## Registry and endpoint lifecycle

The Runtime identity anchor prepares a separate type registry at Begin. Its large
SHM object is allocated lazily on the first valid descriptor registration, rather
than allocating roughly 2.8 MB of three-slot storage for every legacy Runtime.
Internal logical name: `/kcf_introspection_type_<pid>_<start_ticks>`.
Fixed capacity: 64 types, 128 fields each; no resizing, allocator or pointer in SHM.

Storage uses the R2B polling-only SharedChannel TryCreate/TryPublishSnapshot path.
A process-local mutex serializes registration calls; no observer shares this mutex.
Shared notification locks are not used for publication. Large local registry and
client snapshots are heap allocated to avoid megabyte-scale stack objects.

After real Create/Open and optional worker/Watch setup succeed, wrappers generate,
validate and register the declared descriptor before recording their endpoint.
Successful publication assigns EndpointInfo.type_id. Undefined/invalid types,
registry creation/publication failure, capacity exhaustion or conflicting metadata
leave that endpoint's type_id=0 without changing IPC results. diagnostic_type_name
remains compiler-specific human-readable text, never a decode identifier.

The EndpointRegistry internal protocol is bumped from 1 to 2 for the added type_id
field. Its client requires the new protocol/size; old experimental R2A storage is
not reinterpreted using the new layout. Other registry protocol versions stay unchanged.

Same ID and identical canonical name/layout/ordered fields reuse the first descriptor.
Comparison ignores padding, reserved bytes, unused fields and bytes after the first
NUL. Registered metadata is normalized. Same ID with differing meaningful content
returns 0 for the new endpoint; the original descriptor and existing endpoints remain
unchanged. ID collisions across different canonical names are handled as conflicts.
Cross-process equal IDs do not by themselves imply identical local layouts.

Descriptors stay for the Runtime lifecycle even after their endpoints close. They
are not reference-counted or evicted; repeated endpoint creation reuses them.
Normal Runtime end closes/unlinks storage. Crash may leave stale storage, rejected
by generation validation; there is no global stale cleaner.

A slow/killed reader can pin slots. A new descriptor append then returns 0 on
-EAGAIN and rolls back the local append; existing published descriptors are preserved.
No partially published descriptor ID is assigned. Existing type_id=0 endpoints are
not retroactively upgraded: recreate/register at a later lifecycle opportunity.
Permanent abandoned pins can prevent further descriptor publication until Runtime
restart; real endpoint/data behavior continues. Lifecycle allocation/system costs
remain; this is not a hard real-time guarantee against OS scheduling/resource failure.

## Lookup and validation

```cpp
std::vector<kcf::TypeDescriptor> types;
client.ListTypes(runtime, types);

kcf::TypeDescriptor descriptor;
if (endpoint.type_id != 0) {
    int result = client.GetType(runtime, endpoint.type_id, descriptor);
}
```

Both calls preserve output on error. ListTypes returns an all-valid vector or
negative errno; one malformed entry rejects the entire snapshot with -EPROTO.
GetType rejects ID 0 with -EINVAL and reports unknown ID with -ENOENT.
If no type registry exists (including a Runtime with only undefined types), the
lookup reports the storage error, normally -ENOENT. It does not fabricate descriptors.
A valid stored empty snapshot would return success with an empty vector.

Validation on registration and client reads includes:

- Matching PID/start ticks before/after reading, registry protocol/struct size and
  type_count <= 64; unique nonzero type IDs.
- Descriptor protocol/struct size, nonempty terminated canonical name and its hash,
  nonzero payload size, power-of-two alignment and compatible payload-size multiple.
- field_count in 1..128, nonempty terminated field names, unique names, valid kinds,
  exact primitive element_size and array_count >= 1.
- Bounds checked using wide arithmetic and remaining payload bytes; overlapping
  fields are rejected, including union-like aliasing. Unaligned offsets are allowed
  for explicitly packed data; future readers must copy bytes rather than dereference
  potentially unaligned typed pointers.

## Semantic identity versus local ABI

The type ID names a semantic contract independently of compiler/runtime identity.
Offsets, payload_size and alignment describe the actual declaring binary's layout.
They are not portable wire-layout guarantees. Current scope is local native KCF
payload representation on the same Linux host; R3 is not endian conversion or a
serialization protocol. A future reader must check the selected endpoint's payload
size against its descriptor and use validated field bounds for the same generation.
ID alone is insufficient to decode bytes, and diagnostic_type_name is never sufficient.

```text
/example_odometry
  type_id → example.Odometry.v1
            sequence       UINT64
            timestamp_us   UINT64
            x              FLOAT32
```

No raw Topic data reader, dynamic Parameter get/set, Tool Interface, Service
introspection, Qt or serialization is implemented. Existing typed IPC in tests
only verifies compatibility and failure isolation.

## Hot path and tests

Descriptor work is confined to endpoint creation/open. Publish, subscriber delivery,
Parameter Get/Set and ProcessRuntime Loop contain no type lookup/registry call.

```sh
cmake -S . -B build
cmake --build build -j 4
./build/examples/introspection/kcf_type_descriptor_test
```

Tests cover known FNV output/version distinction and cross-process ID resolution;
all 11 primitive helper kinds; exact TestData offsets/widths/counts; fixed float array;
flattened nested fields; Publisher/Subscriber/Parameter dedup; unchanged IPC for
undefined, malformed and conflicting descriptors; 64-type capacity with a new typed
Parameter still working with type_id=0; slow/killed observer pin isolation;
normal cleanup; malformed stored metadata rejection; and the full
Supervisor → membership → Runtime → Endpoint → type_id → GetType chain.

The pin fixture is test-only and adds no production failure-injection API.
