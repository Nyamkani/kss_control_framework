# R2B.1 — Application-Scoped SystemStatus

SystemStatus storage now belongs to a Supervisor process instance, identified by
its PID and Linux `/proc/<pid>/stat` start ticks. Application names are display
metadata only. Two Supervisors, including two with the same application name,
can own independent SystemStatus channels concurrently.

## Scope and lifetime

`Bringup::Setup()` calls `SystemStatusPublisher::CreateForApplication()`. This
resolves the current process identity once and retains the resulting scope.
`Process::Start()` prepares `KCF_SYSTEM_STATUS_SCOPE=<pid>_<start_ticks>` in the
child's exec environment, alongside the existing supervision FD. It does not
mutate the Supervisor's process environment and performs no allocation after
fork. An explicit scope replaces any scope inherited by a nested Supervisor.

The logical SystemStatus name is `/kcf/system/status/state_<pid>_<start_ticks>`.
SharedParameter's existing name encoding produces the physical SHM object;
application code does not assemble it. Topic, Parameter and Service namespaces
are otherwise unchanged.

Reset retains the same Supervisor PID/start ticks, publisher mapping and storage
inode. New child processes receive the same scope. Normal shutdown closes and
unlinks only the owned object. SIGKILL may leave a stale object; a different
Supervisor generation has a different name and does not collide with it. Existing
SharedParameter dead-owner recovery remains available, but this change adds no
background garbage collector or cross-Application cleanup.

## Public API and compatibility

Existing child code continues to use:

```cpp
kcf::SystemStatusSubscriber subscriber;
subscriber.Open(callback);
```

Open resolves the inherited scope once. Publish, ReadCurrent and worker reads
retain their existing SharedParameter synchronization and notification paths;
there are no scope/discovery or `/proc` lookups in those paths. Invalid nonempty
scope tokens fail with `-EINVAL`, without falling back to global storage.

Observers outside the child exec tree must select a Supervisor identity explicitly:

```cpp
subscriber.OpenForApplication(supervisor.pid,
                              supervisor.process_start_ticks,
                              callback);
```

This accepts public identity values, not physical SHM names. The two-argument
`Process::Start(executable, args)` source API remains usable; its optional third
argument allows Framework-owned exec setup to propagate the scope.

With no inherited scope, direct SystemStatusPublisher::Create and Subscriber::Open
retain the legacy global standalone behavior. ProcessRuntime does not acquire a
new SystemStatus subscription or worker merely because it is standalone.
A standalone observer can explicitly choose a Supervisor with OpenForApplication.
An external observer that previously used no-argument Open to watch the only
Bringup must now specify its identity. Automatic global fallback would silently
select the wrong Application, so it is intentionally not provided.

Rebuild and restart Supervisor and child binaries together to adopt this naming
contract. SHM storage format remains **3**, Service protocol remains **2**, and
SystemStatus layout remains **96 bytes**. There is no mixed old/new supervised
binary compatibility adapter; an old child still resolves the old global name.

## Validation

Clean Framework build:

```sh
cmake -S . -B build-r2b1
cmake --build build-r2b1 -j4
./build-r2b1/examples/supervisor/kcf_application_scope_test
```

The new real fork/exec test runs two actual Bringups, each with an observing child
and a worker. It checks different names and identical names, inherited-parent
scope replacement, both directions of ERROR observation/isolation, both Reset
paths, unchanged Supervisor scope, independent shutdown, SIGKILL/stale restart,
invalid scope rejection, and the legacy unscoped API. Crash cleanup in the test
reclaims only its own known dead-owner object using existing SharedParameter
recovery, then unlinks it as owner. Production does not perform that test cleanup.

Existing Reset tests now inspect the scoped object's inode and confirm it stays
unchanged across Reset. External health/discovery test observers explicitly pass
Supervisor identity. Existing child application API calls are unchanged.

## KT-7 real multi-Application validation

The separate validation project reads the existing Tool UI/backend/fixture source
files without changing them. It is optional and does not add Qt or Tool
requirements to the Framework build:

```sh
cmake -S examples/introspection/kt7_validation -B /tmp/r2b1-kt7-validation \
  -DKCF_TOOLS_SOURCE_DIR=/home/kssvm/workspace/kcf/kcf_tools \
  -DCMAKE_PREFIX_PATH=/opt/Qt/6.9.3/gcc_64
cmake --build /tmp/r2b1-kt7-validation -j4
ctest --test-dir /tmp/r2b1-kt7-validation --output-on-failure
```

It starts Application A (one child), Application B (two children) and one standalone
runtime concurrently. The unchanged MainWindow must discover both application
hierarchies, associate each runtime's Topics/Parameters/Services correctly,
navigate to existing Echo/Editor/Call screens, clear stale selections on A's Reset,
retain B's children, and keep B functional after A exits.

The existing Tool regression suite is also rebuilt against the updated Framework
in `/tmp/kt7-r2b1-build`. The prior Tool KT-7 report is left untouched as historical
evidence of the pre-R2B.1 `-EEXIST` limitation; the result here supersedes it.
